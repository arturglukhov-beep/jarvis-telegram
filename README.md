# Jarvis в Telegram — текстовая версия

Подготовлена для @bestsled1126_bot на текущем сервере Артура. Исходная папка `/home/agent/bot` не изменена; предыдущая точка входа сохранена в `legacy/` и не используется.

## Что работает в этой версии

- Только личный чат владельца, привязка по одноразовому коду или OWNER_ID.
- Вопросы и подготовка текстов через Codex App Server, общая память из `/home/agent`, дневники за последние три дня по Камчатке.
- Сохранение thread между сообщениями и перезапусками; `/new`, `/stop`, `/help`, `/status`.
- Ограниченная очередь, запрет второй копии на сервере, защита от повторной обработки update после сбоя.

Выполнение команд, изменение файлов, отправка сообщений другим людям, распознавание голоса, вложения, расписания, выбор моделей и поиск через внешние сервисы отключены. Изоляция команд в текущем окружении возвращает ошибку bwrap. Этот выпуск не означает выполнения всего исходного плана.

## Подключение владельцем

В терминале сервера:

```bash
cd /home/agent/projects/jarvis-telegram
npm run setup
npm run check
npm start
```

Настройка скрыто запрашивает токен и сохраняет его в `/home/agent/.config/jarvis-telegram/env` с правами 0600. При отсутствии OWNER_ID покажет одноразовую команду `/start КОД` для личного чата с ботом. Секрет и код не передавать в переписке и не публиковать. Существующая конфигурация автоматически не перезаписывается.

До ввода настоящего токена `npm run check` завершается кодом 1 с перечнем недостающих полей — это ожидаемо. Проверка не обращается к Telegram и модели.

Перед polling программа проверяет getMe и отсутствие webhook. Другой username или существующий webhook останавливают запуск. Webhook не удаляется, накопленные updates не отбрасываются. Исходящая доставка допустима только в личный чат привязанного владельца.

## Проверка и авторизация

```bash
npm ci --ignore-scripts
npm test
npm audit --omit=dev
npm run metadata
```

`metadata` проверяет инициализацию App Server и наличие авторизованного аккаунта без создания turn и запроса к модели. Оно не доказывает доступность модели или наличие лимитов. Живая проверка ответа выполняется владельцем после подключения и использует лимиты его аккаунта Codex.

Закреплены Node.js 24.22.3, grammY 1.43.0 и Codex 0.169.0-alpha.11.1. Бинарный файл Codex скопирован в `/home/agent/.local/bin/jarvis-codex`, отдельно от расширения IDE. Зависимости закреплены в package-lock.json. Схема протокола находится в protocol/.

Приватный runtime: `/home/agent/.local/share/jarvis-telegram`. В нём отдельная конфигурация Codex, рабочая папка без пользовательских проектов и state.json. Авторизация связывается с существующим входом Codex; токены Telegram и API не передаются в окружение дочернего процесса. Все запросы на разрешения отклоняются, shell, apps, браузер и другие инструменты отключены, sandbox — read-only. При изменённой конфигурации runtime запуск останавливается.

## Автозапуск после проверки в личном чате

Шаблон deploy/jarvis-telegram.service подготовлен для системного systemd. Установку выполняет администратор после проверки токена и остановки ручного процесса:

```bash
sudo install -m 0644 deploy/jarvis-telegram.service /etc/systemd/system/jarvis-telegram.service
sudo systemctl daemon-reload
sudo systemctl enable --now jarvis-telegram.service
sudo systemctl status jarvis-telegram.service --no-pager
```

В этой подготовке служба не устанавливалась и не запускалась. Для остановки: `sudo systemctl stop jarvis-telegram.service`. Не запускать второй polling-процесс с тем же ботом на другом сервере.

## Ошибки и восстановление

После сбоя уже принятый update автоматически не выполняется повторно: результат мог не успеть дойти до Telegram. Повторите свой вопрос вручную, если ответ отсутствует. Активные незавершённые запросы не восстанавливаются автоматически.

Повреждённое состояние не сбрасывается молча. Сохраните state.json и обратитесь к диагностике; не удаляйте файл для повторной привязки. Старые диалоги Codex при `/new` не удаляются. Для нового входа или сброса токена потребуется отдельная настройка; секреты и сырые ошибки SDK в логи не выводятся.

При переносе на другой сервер отдельно устанавливаются Node.js, закреплённый Codex CLI, его авторизация и файлы памяти. Архив исходников не содержит настоящих секретов, node_modules, бинарного CLI или runtime.
