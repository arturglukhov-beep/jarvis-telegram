# Jarvis в Telegram

## Версия 0.3.1: обновление существующих диалогов

Установленный Codex сохраняет начальные developer-инструкции при thread/resume: передача новых developerInstructions не заменила старое ограничение текстового режима. Контроллер теперь явно добавляет текущие доверенные инструкции через thread/inject_items перед первым продолжением диалога в новом процессе или после изменения политики. Исходные ID и переписка сохраняются; при неудаче обновления запрос прерывается. Это не меняет native permissions и подтверждения действий.

## Версия 0.3.0: подтверждаемые команды

Артур установил точечный AppArmor-профиль; selftest sandbox прошёл чтение/запись внутри, запрет доступа вне корня, symlink escape и запрет сети. Команды подключены через структурированное предложение `command`: `argv` — явный список аргументов, `cwd` — каталог проекта, по умолчанию command-playground. Нативные shell-tools модели остаются выключенными; её текст сам по себе не исполняется.

Перед подтверждением создаётся замороженная копия проекта и показываются полная команда, исходный каталог и SHA-256 копии. Запуск происходит в отдельном namespace и transient user service: 512 МБ памяти, 32 процесса, CPU 100%, 30 секунд; рабочая файловая система tmpfs — 64 МБ. Исходные файлы не меняются, сеть отключена. Изменения проекта выполняются отдельным подтверждаемым write_file.

Внешний namespace монтирует только readonly публичные /usr/runtime, фиксированный bwrap и файлы конкретного задания; весь host root не монтируется. Во внутреннем профиле полностью сохранены deny для /home/agent, /tmp и /run/user. Публичные Node/CLI находятся в приватном /var/tmp/jarvis-command-runtime-UID, без авторизации. Доверенный bootstrap и bounded stdout relay устанавливаются `python3 scripts/install-command-runtime.py`; служба проверяет/восстанавливает публичный runtime при старте. Команды исполняются с очищенным окружением, без BOT_TOKEN/API-ключей.

В копию не входят скрытые файлы, .git, node_modules, symlinks/hardlinks, auth/env/credentials и обнаруженные буквальные секреты. Это может мешать тестам, которым нужны оригинальные зависимости или конфигурация. Предел копии: 25 МБ/2000 записей/12 уровней; файлы до 5 МБ. После 30 подготовленных копий потребуется согласованное архивирование. Копии не удаляются автоматически; результаты выполнения хранятся в tmpfs и после завершения исчезают. Вывод ограничен 200000 байт, большие текстовые результаты прикрепляются файлом.

Каждая команда требует одноразового подтверждения владельца. /stop отменяет активные command callbacks и останавливает соответствующую transient service. Потеря sandbox, ресурсов или runtime не приводит к запуску вне изоляции. Проверка sandbox обновляется при устаревании, максимум через сутки.

Сведения о первоначальной блокировке shell ниже относятся к предыдущим версиям.

## Версия 0.2.0: вложения, голос, файлы и напоминания

Добавлены фотографии PNG/JPEG, UTF-8 документы и PDF до 5 МБ (PDF до 30 страниц, без OCR), голосовые до 2 минут. Голос распознаётся локально через faster-whisper/base CPU int8; отдельный платный API не подключён. Установщик: `python3 scripts/install-media.py`; закреплённые Python-зависимости — deploy/media-requirements.txt.

Codex возвращает текст и структурированные предложения контроллеру. Чтение/запись файлов допускаются только внутри /home/agent/projects, кроме самого бота, tgbotdorabotka, скрытых каталогов и секретов. Запись до 16000 символов показывает полное содержимое, идентификатор и точную привязку кнопки к предпросмотру; требует одноразового подтверждения. Перед перезаписью сохраняется приватная резервная копия. Удаление не реализовано. Содержимое прочитанного файла доставляется целиком вложением.

Напоминания создаются только владельцу после подтверждения текста и времени: одноразовые или ежедневные по Камчатке. Команда /reminders показывает задачи. Отмена не удаляет историю. Неопределённая доставка получает статус unknown и не повторяется автоматически; просроченные во время простоя одноразовые задачи помечаются missed. /stop отменяет очередь, распознавание и неподтверждённые действия.

Изоляция произвольных shell-команд остаётся заблокированной AppArmor userns на сервере. Недостающий codex-resources/bwrap восстановлен; глобальные sysctl и AppArmor не отключались. Подготовлен узкий профиль для этого binary. Администратор применяет его из терминала сервера:

    sudo sh /home/agent/projects/jarvis-telegram/scripts/install-sandbox-profile.sh
    node /home/agent/projects/jarvis-telegram/scripts/check-sandbox.js

Selftest проверяет разрешённое чтение/запись, отказ чтения и записи вне корня, escape через symlink и запрет сети; запускается с NoNewPrivileges, как пользовательская служба. До успешного selftest выполнение shell-команд не включается. Прохождение selftest само по себе не включает shell: затем подключаются и проверяются его запросы разрешений.

Вложения хранятся в приватном runtime без автоматического удаления; лимит — 200 файлов/500 МБ. Если он достигнут, владельцу потребуется отдельно согласовать архивирование или очистку. Секреты и runtime не входят в архив исходников.

Ниже сохранена документация первоначального текстового запуска; сведения о возможностях выше имеют приоритет.

Подготовлена для @bestsled1126_bot на текущем сервере Артура. Исходная папка `/home/agent/bot` не изменена; предыдущая точка входа сохранена в `legacy/` и не используется.

## Что работает в этой версии

- Только личный чат владельца, привязка по одноразовому коду или OWNER_ID.
- Вопросы и подготовка текстов через Codex App Server, общая память из `/home/agent`, дневники за последние три дня по Камчатке.
- Сохранение thread между сообщениями и перезапусками; `/new`, `/stop`, `/help`, `/status`.
- Ограниченная очередь, запрет второй копии на сервере, защита от повторной обработки update после сбоя.

Выполнение команд, изменение файлов, отправка сообщений другим людям, распознавание голоса, вложения, расписания, выбор моделей и поиск через внешние сервисы отключены. Изоляция команд в текущем окружении возвращает ошибку bwrap. Этот выпуск не означает выполнения всего исходного плана.

## Подключение владельцем

В терминале сервера:

```bash
cd /home/agent/projects/jarvis-telegram
npm run setup
npm run check
npm start
```

Настройка скрыто запрашивает токен и сохраняет его в `/home/agent/.config/jarvis-telegram/env` с правами 0600. При отсутствии OWNER_ID покажет одноразовую команду `/start КОД` для личного чата с ботом. Секрет и код не передавать в переписке и не публиковать. Существующая конфигурация автоматически не перезаписывается.

До ввода настоящего токена `npm run check` завершается кодом 1 с перечнем недостающих полей — это ожидаемо. Проверка не обращается к Telegram и модели.

Перед polling программа проверяет getMe и отсутствие webhook. Другой username или существующий webhook останавливают запуск. Webhook не удаляется, накопленные updates не отбрасываются. Исходящая доставка допустима только в личный чат привязанного владельца.

## Проверка и авторизация

```bash
npm ci --ignore-scripts
npm test
npm audit --omit=dev
npm run metadata
```

`metadata` проверяет инициализацию App Server и наличие авторизованного аккаунта без создания turn и запроса к модели. Оно не доказывает доступность модели или наличие лимитов. Живая проверка ответа выполняется владельцем после подключения и использует лимиты его аккаунта Codex.

Закреплены Node.js 24.22.3, grammY 1.43.0 и Codex 0.169.0-alpha.11.1. Бинарный файл Codex скопирован в `/home/agent/.local/bin/jarvis-codex`, отдельно от расширения IDE. Зависимости закреплены в package-lock.json. Схема протокола находится в protocol/.

Приватный runtime: `/home/agent/.local/share/jarvis-telegram`. В нём отдельная конфигурация Codex, рабочая папка без пользовательских проектов и state.json. Авторизация связывается с существующим входом Codex; токены Telegram и API не передаются в окружение дочернего процесса. Все запросы на разрешения отклоняются, shell, apps, браузер и другие инструменты отключены, sandbox — read-only. При изменённой конфигурации runtime запуск останавливается.

## Автозапуск после проверки в личном чате

На текущем сервере 14.11.2026 запущена пользовательская служба из `deploy/jarvis-telegram.user.service`. Она подключена к default.target пользователя agent; Linger=yes позволяет работать после выхода. Управление: `systemctl --user status jarvis-telegram.service`, `systemctl --user restart jarvis-telegram.service`, `systemctl --user stop jarvis-telegram.service`. Пользовательская версия не включает требующие административных прав настройки файловых namespace из системного шаблона; ограничения инструментов Codex сохраняются.

Шаблон deploy/jarvis-telegram.service подготовлен для системного systemd. Установку выполняет администратор после проверки токена и остановки ручного процесса:

```bash
sudo install -m 0644 deploy/jarvis-telegram.service /etc/systemd/system/jarvis-telegram.service
sudo systemctl daemon-reload
sudo systemctl enable --now jarvis-telegram.service
sudo systemctl status jarvis-telegram.service --no-pager
```

Системная версия службы не устанавливалась; на текущем сервере используется пользовательская версия, описанная выше. Не устанавливать обе одновременно. Для остановки системной версии: `sudo systemctl stop jarvis-telegram.service`. Не запускать второй polling-процесс с тем же ботом на другом сервере.

## Ошибки и восстановление

После сбоя уже принятый update автоматически не выполняется повторно: результат мог не успеть дойти до Telegram. Повторите свой вопрос вручную, если ответ отсутствует. Активные незавершённые запросы не восстанавливаются автоматически.

Повреждённое состояние не сбрасывается молча. Сохраните state.json и обратитесь к диагностике; не удаляйте файл для повторной привязки. Старые диалоги Codex при `/new` не удаляются. Для нового входа или сброса токена потребуется отдельная настройка; секреты и сырые ошибки SDK в логи не выводятся.

При переносе на другой сервер отдельно устанавливаются Node.js, закреплённый Codex CLI, его авторизация и файлы памяти. Архив исходников не содержит настоящих секретов, node_modules, бинарного CLI или runtime.
## Версия 0.3.2: доступ к установленным инструкциям

Telegram использует отдельный CODEX_HOME; каталог skills основного Codex сам по себе в него не попадает. Контроллер добавляет каталог доверенных SKILL.md из skills/global, skills/custom, skills/senior-fullstack и закреплённого Superpowers 7.0.1. Дубликат content-creator выбирается из custom. Поддерживаются YAML и прежний Markdown без frontmatter.

Команда /skills показывает каталог владельцу без обращения к модели. Сейчас это 38 инструкций: 22 проектных, system и 15 Superpowers. Отдельных reminder и server-setup на диске нет; напоминания реализованы контроллером, для сервера установлен server-management.

Модель запрашивает внутреннее действие load_skill с точным именем. Контроллер читает ограниченный проверенный файл, обновляет developer context сохранённого диалога и продолжает задачу. До трёх раундов, максимум девять инструкций и 192000 байт на запрос. Промежуточные ответы и действия не отправляются пользователю; смешивание с исполняемыми действиями отклоняется. /stop прерывает весь запрос. Ссылки, изменившиеся файлы, произвольные пути и инструкции больше 64000 байт отклоняются.

Скиллы дают инструкции, а не дополнительные инструменты. Native shell/apps остаются выключены. Веб-поиск, скачивание URL, генерация изображений, внешние интеграции, делегирование и администрирование не подключены. Связанные reference-файлы и скрипты скиллов автоматически не загружаются. Действуют прежние подтверждения файлов, команд и напоминаний; команды работают только в изолированной копии.
