# Расширение Telegram Jarvis: проверка и исправление

Основание: Артур поручил проверить и исправить ограничения команд, файлов, голосовых, вложений и расписания. Базовый план: ../tgbotdorabotka/PLAN.md. Текстовый канал уже принят владельцем.

## Решения и границы

- Существующие привязка, история и секреты сохраняются. Новая версия включается только после тестов и ревью.
- Native shell остаётся выключенным до успешной проверки изоляции чтения, записи и сети. Не отключать AppArmor или sandbox глобально.
- Полный комплект закреплённого CLI должен включать codex-resources/bwrap; этот файл восстановлен.
- Для Ubuntu подготовить точечный AppArmor профиль bubblewrap и административный установщик. Его применение требует sudo владельца; автоматически обходить пароль нельзя.
- Операции с файлами выполняет контроллер по строгому списку корней /home/agent/projects, исключая самого бота, .git и секреты. Запись показывает полный путь и содержимое и требует одноразового подтверждения. Удаления нет.
- Модель возвращает структурированные предложения; текст модели не является исполняемой командой. Вложения не разрешают операции без подтверждения владельца.
- Вложения: ограниченные по размеру фотографии, UTF-8 текст/код, PDF с ограничением страниц и извлечения. Архивы и исполняемые файлы не запускать.
- Голос: локальный faster-whisper (CPU/int8, модель base), без платного API и передачи аудио стороннему распознавателю. Распознавание ограничено по длине/времени.
- Напоминания только владельцу, одноразовые и ежедневные, Asia/Kamchatka. Создание подтверждается с полным текстом/временем; отмена меняет статус, не удаляет историю. Ошибка доставки не вызывает автоматический повтор с неопределённым результатом.

## Шаги

1. Диагностика и комплект CLI. Проверить userns, bwrap, Landlock; восстановить ресурс; подготовить profile/install/selftest. Не считать исправлением только наличие файла.
2. Файловая политика и одноразовые подтверждения. Тесты traversal, symlink, защищённые каталоги, повтор/чужой/просроченный callback. Реализация и коммит после зелёных тестов.
3. Планировщик. Тесты времени Камчатки, следующего дня, перезапуска, повторного тика и неизвестной доставки. Сохранение задач до попытки отправки.
4. Медиа и локальная речь. Тесты размера, MIME/magic, UTF-8, PDF/фото, безопасного скачивания и ошибок распознавания. Установить локальные зависимости, проверить на публичном тестовом аудио без inference Codex.
5. Структурированные ответы Codex и Telegram UI. Передавать изображения нативно, документы/транскрипты как недоверенные данные. Кнопки исполняют только проверенные сервером операции; /stop отменяет подготовку/очередь.
6. Сквозные тесты, независимое ревью, исправления, audit. Затем контролируемый перезапуск пользовательской службы, проверка сохранённого владельца/истории. Не посылать сообщения без запроса владельца.
7. Передать Артуру конкретную оставшуюся административную команду для userns, если sudo по-прежнему недоступен; до её успешной проверки native shell не включать.
